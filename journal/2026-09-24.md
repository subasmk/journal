## Self-Check Questions

**1. What is the difference between `except Exception` and a bare `except:`?**
- `except Exception` catches all exceptions that inherit from `Exception` class (most regular errors). A bare `except:` catches EVERYTHING including system-exiting exceptions like `KeyboardInterrupt` and `SystemExit`, which is why it's considered bad practice — it can prevent proper program shutdown.

**2. How do you create a custom exception in Python?**
- Create a class that inherits from `Exception` (or a more specific exception class):
  ```python
  class InvalidAgeError(Exception):
      pass
  ```
  Then raise it with `raise InvalidAgeError("message")`.

**3. What does a list comprehension look like, and when is it useful?**
- Syntax: `[expression for item in iterable if condition]`
- Useful when you need to create a new list by transforming or filtering items from an existing iterable. More concise and often faster than a traditional for-loop.

**4. How do you check the status code of a `requests` response?**
- Access `response.status_code` attribute. Common codes: 200 (OK), 201 (Created), 400 (Bad Request), 401 (Unauthorized), 404 (Not Found), 500 (Server Error).

**5. What is the purpose of `requirements.txt`?**
- Lists all Python package dependencies for a project with their versions. Used to recreate the same environment elsewhere with `pip install -r requirements.txt`. Ensures consistency across different machines/setup.

## My Answers

1. Bare `except:` catches everything including system exceptions. `except Exception` is safer.
2. Subclass `Exception`: `class MyError(Exception): pass`
3. `[expr for x in iterable if cond]` — concise list creation with transformation/filtering.
4. `response.status_code` — 200 OK, 404 Not Found, etc.
5. Lists dependencies for reproducibility — `pip install -r requirements.txt`.
